# Why

Kiln #49 and #51 require an opt-in host composition with separate coordinator, executor and publisher authority and reusable pinned worker guests. Existing canary and static guests must not acquire new permissions.

# What Changes

Add a native NixOS/Clan deployment composition, immutable guest package, explicit compatibility and placement admission, durable closure retention and executable qualification tools. Existing owner protocols remain authoritative; missing upstream gateway, inference, continuation or hardware qualifications remain blocked rather than replaced.

# Impact

onix-core module maintainers own deployment. Kiln owns claims and publication; Lattice owns workflow persistence; Cairn owns lifecycle. No deployment, activation, pin update or remote effect is authorized.
