# Design: canonical Artifact admission

## Success contract

Complete means two independent fresh credential-free exact-object HTTPS fetches and revision/type/archive evidence, preserved read-only/private rejection, exact managed policy reconciliation, truthful deployed-role evidence, and accepted lifecycle gates. Policy declaration, publication, local cache, or deployment alone does not prove acquisition.

## Policy model

Append canonical Artifact after koiTerminal in the shared ordered public catalog and both exact-set validators. Update paired positive/negative current fixtures, not historical receipts. Public membership is seven; private membership stays four; desired native policy count is eleven. Bounded Exec remains the only CI RID.

## Governance and authority

Use the existing threshold-one Choregraph/durable-file precedents. Import or synchronize only already-public signed state through existing authorized owner mechanisms; never generate node keys or mutate producer identity, delegate, threshold, main, or refs. Hosting authorization is explicit and distinct from publication and consumer selection.

## Deployment

Freeze implementation, pass focused owner policy/receipt checks and target closures, then use documented strict-host-key Clan operations for required serving roles. Reconcile exact sets and inspect live closures/identities without exposing secrets. Missing host, authority, or tooling remains a blocker; do not invent a transport or claim an undeployed role.

## Evidence

Use typed Nickel exported to JSON with BLAKE3. Distinguish staged/blocked from accepted evidence. Record only observed facts, preserve historical receipts, bind both consumer SHAs, public policy, unchanged CI/private sets, signed producer identity, actual closure identities and negative probes. Fresh HTTPS clients use empty HOME/config/cache, no credential helpers/prompts/SSH/ambient headers/config. No GitHub fallback.

## Failure and rollback

Stop acceptance on failed gates or probes; retain signed storage and existing node identity. Rollback only the scoped serving configuration through documented generation rollback; never delete repository storage or keys. Do not claim rollback without execution.
