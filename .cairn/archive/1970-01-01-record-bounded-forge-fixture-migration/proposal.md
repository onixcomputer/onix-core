# Change: Record the first controlled forge fixture migration

## Why

The accepted Valence forge-operations implementation has temporary-repository evidence but no production-host observation. The operator authorized the reviewed controlled Bounded Exec fixture without requiring a source-host API export. onix-core must retain the exact plan, native observations, offline bindings, idempotent replay, seed convergence, and unchanged canonical-ref boundary without promoting fixture attribution into source truth or review authority.

## What Changes

- Retain the normalized two-record fixture, deterministic plan, native built-in observations, and offline-verifiable Valence binding. r[onix.radicle_forge_ops.controlled_fixture]
- Record ordinary Radicle issue/patch visibility, attribution-only review treatment, Author `parent` signed refs, Aspen/desktop/HTTPS convergence, and unchanged canonical `main`. r[onix.radicle_forge_ops.live_observation]
- Retain a `verify_existing` replay whose native execution changes zero refs and whose second binding verifies offline. r[onix.radicle_forge_ops.idempotent_replay]
- Preserve explicit non-claims for source export, actor authenticity, semantic equivalence, approval, canonical authority, CI correctness, durability, and release readiness. r[onix.radicle_forge_ops.boundaries]

## Impact

- **Runtime:** Adds collaboration metadata in the Author namespace only; no service configuration, CI scope, deployment, or canonical ref changes.
- **Evidence:** Adds typed and raw artifacts under `evidence/radicle/`.
- **Compatibility:** Existing Bounded Exec source, patch, CI, identity, and publication objects remain unchanged.
