# Recover the ttWKV7 boundary preflight

## Problem

The explicitly authorized argument-free boundary runbook terminated before its execution lock, owner isolation, device process, or rollback because the pinned loopback ED25519 host fingerprint no longer matched the current host key. The terminal root proves every process, isolation, restoration, service-stop, and rollback counter remained zero, but the accepted plan still names that occupied root and the archived runbook installed classification/restoration traps only after early authority checks.

## Proposed change

Preserve the failed preflight as a deterministic `not_run` receipt, issue a second immutable session plan with a distinct root, bind the current loopback ED25519 fingerprint, and move terminal classification coverage ahead of every fallible preflight after root creation. Retain the exact device, package, fixture, one-process budget, timeout, owner, rollback, evidence, and no-retry controls.

## Impact

A later explicit authorization can target one corrected argument-free runbook without deleting or reusing the first evidence root. This change remains software-only and does not authorize hardware execution, owner isolation, service changes, device access, or a retry.
