# Tenstorrent native runtime delta

## ADDED Requirements

### Requirement: Device-4 persistent run boundary is immutable before authorization

The repository MUST provide one argument-free, recoverable, single-attempt runbook for the fresh `rwkv-ttwkv7-persistent-device-4` session, MUST bind the diagnostic-safe response transport and exact immutable package/readiness authorities, MUST validate complete process, numerical, artifact, owner, and board evidence before any success classification, and MUST remain device-free until separate explicit hardware authorization. r[onix.tenstorrent.native_runtime.rwkv_lab.ttwkv7_persistent_metalium_device_4_runbook]

#### Scenario: Preparation cannot consume hardware authorization

- **GIVEN** the fresh device-4 session package and terminal tasks `30`, `64`, and `281`
- **WHEN** package, runbook, checker, mutation, formatting, Nix, closure, or lifecycle validation runs
- **THEN** validation SHALL NOT create the declared runtime root, query a board, stop the owner, open a device, execute a kernel, invoke the runbook, or reuse a terminal attempt

#### Scenario: One future invocation remains bounded

- **GIVEN** a separately authorized invocation of the archived runbook
- **WHEN** its atomic invocation lock is consumed
- **THEN** it SHALL run at most one host process with one persistent Metalium child, one MeshDevice, one response connection, calls `0..23`, twelve continuity links, and zero retries, reconnects, fallback commands, or suffix arguments

#### Scenario: Diagnostic streams remain outside protocol evidence

- **GIVEN** separate `server-stdout.log`, `server-stderr.log`, and canonical response-channel frames
- **WHEN** the host artifact manifest is validated
- **THEN** the exact seven-line manifest SHALL bind all six artifacts, stdout/stderr SHALL remain diagnostics only, the response socket SHALL be absent after exit, and every accepted response SHALL begin with canonical magic at response-channel byte zero

#### Scenario: Restoration remains part of terminal classification

- **GIVEN** any exit after rollback-arm or owner-isolation attempt
- **WHEN** the runbook restores the owner and captures board and service evidence
- **THEN** a safe success SHALL require complete artifacts, healthy board evidence, owner restoration, and HTTP `200` within the full 600-second window; an incomplete or late recovery SHALL remain `unsafe` without later upgrade

#### Scenario: Mutations fail closed

- **GIVEN** the reviewed package, plan, host key, process budget, artifact schema, response-channel authority, and restoration lifecycle
- **WHEN** any authority, count, hash, path, invocation, timeout, service, health, manifest row, response connection, or retry prohibition changes
- **THEN** the checker SHALL reject the runbook before it can be archived as authorized execution evidence
